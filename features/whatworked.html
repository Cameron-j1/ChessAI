Our Development Journey

Development Journey

From SVM-based evaluation to attention-based neural networks, our project has undergone significant evolution.

Each phase brought new insights and improvements, leading to our current sophisticated chess engine.

Development Phases

  • SVM-based move evaluation with 16,000 games
  • Spatial move prediction with 8x8 representation
  • Attention-based neural network with 3.9M positions

Phase 1: SVM-Based Move Evaluation

Our initial approach focused on traditional machine learning techniques:

  • Data Collection: Gathered 16,000 high-quality games from players rated 2000+ ELO
  • Feature Engineering: Developed a comprehensive set of chess-specific features including material balance, piece-square tables, and king safety
  • Model Training: Implemented an SVM model that learned to evaluate positions based on these features
  • Key Learning: This phase taught us the importance of chess-specific features and the value of high-quality training data

Phase 2: Evolution to Spatial Move Prediction

We recognized the limitations of categorical move prediction and made a significant architectural change:

  • Architectural Shift: Moved from categorical move encoding to a spatial 8x8 board representation
  • Implementation: Developed a dual-output system that predicted source and destination squares separately
  • Key Learning: This change revealed how spatial relationships are crucial for chess understanding

Phase 3: Attention-Based Neural Network

Our final breakthrough came with the implementation of an attention-based architecture:

  • Input Structure: Developed a 13-channel 8x8 representation where each channel represents a piece type
  • Convolutional Foundation: Used convolutional layers to capture local piece patterns and relationships
  • Attention Mechanism: Implemented multi-head attention to understand complex interactions between distant pieces
  • Key Learning: This architecture proved crucial for understanding both tactical and strategic elements of chess

Phase 4: Training and Optimization

Our training process faced unique challenges due to hardware constraints:

  • Limited Dataset Size: Due to PC constraints, we could only load 3.9M positions for training
  • Initial Network Performance: The smaller initial network handled this dataset size well with minimal overfitting
  • Expansion Challenges: When we expanded the network to increase bot strength, we encountered significant overfitting issues

Solutions Implemented

1. Dropout Implementation

During training, dropout randomly sets a fraction of neurons to zero, which:

  • Forces the network to not rely too heavily on specific neurons
  • Prevents memorization of training data
  • Prioritizes generalization over specific pattern recognition

2. Weight Decay

Implemented parameter regularization through weight decay, which:

  • Constrains model complexity by penalizing large weights
  • Encourages the model to prefer smaller weights
  • Prevents overfitting by limiting the model's ability to make sharp, dramatic decisions based on specific inputs
  • Forces the model to generalize rather than memorize specific patterns

These optimization techniques successfully balanced the trade-off between model capacity and generalization, allowing us to maintain strong performance despite the limited training data.

Planned Enhancements

Based on our development journey, we've identified several areas for improvement:

  • Training Enhancement: Exploring self-play and reinforcement learning techniques
